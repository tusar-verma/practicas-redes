Puerto: Entero de 16 bits que junto a la dirección IP de un host forman una identificación que permite armar conexiones entre aplicaciones en distintos hosts. A esto se lo conoce como socket.

Un host recibe paquetes que pueden tener de destino distintas aplicaciones ejecutandose en el mismo, cada uno asociado a un puerto distinto. El protocolo de transporte se encarga de demultiplexar los paquetes a los puertos adecuados.

Sin esta herramienta, no tendriamos la posibilidad de que varias aplicaciones dentro de un host puedan comunicarse en una red todas al mismo tiempo.

**UDP**: provee servicio no confiable y no orientado a conexión. Es decir puede haber perdida de paquetes y el protocolo no implementa mecanismos para solventarlo, y no tiene un mecanismo para pre-establecer una conexión entre los end-points (que podría conllevar por ejemplo, reservar buffers). Tampoco presenta mecanismos para la entrega en orden.
Como no implementa mecanismos de confiabilidad entonces es más rápido que TCP y se puede usar para aplicaciones en los que la pérdida de algunos paquetes no sea tan importante como gaming, transmisión de voz o video, o la comunicación con servidores DNS que debe ser lo más rápida posible para resolver todos los niveles de la jerarquía y responder al cliente la IP buscada.

**TCP**: es confiable y orientado a conexión. Implementa mecanismos para solventar la perdida de paquetes (basicamente retransmisiones), para el control de flujo, el control de congestión y entrega en orden. Y es orientado a conexión: hay un intercambio de mensajes inicial que sirve para reservar recursos entre los end-points. Estos recursos se usan para proporcionar las garantías mencionadas (control de flujo, entrega en orden, control de congestión). 
Ejemplos de uso son: todos los documentos de la web, SMTP (mandar mails), SSH.
